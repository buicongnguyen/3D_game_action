# Coin and diamond pickups — 2026-09-20

Implemented in Marching and Story. Scrap / shell parts use embossed gold coins; other pickups use faceted colored diamonds. Amber = fuel reserve, cyan = pressure, green = repairs / Story supplies, blue = mine, silver-blue = armor, purple = weapon parts. Existing names, prices, resource values, saves and uses are preserved. The inventory guide explains the visual mapping; Story receipts name coins and supply diamonds.

Player-earned combat loot is auto-collected at long range, including laser, rifle and rocket kills. Marching retains its brief drop-settle animation and nearby magnetic pull, but the old 32 m boundary no longer strands credited drops. Story credits distant rewards immediately, before chapter-end logic can discard them. A player hit retains reward credit even when a turret or lingering burn finishes the enemy. Uncredited turret/stone kills and unrelated map supplies retain proximity collection. Shooting itself still obeys range and wall collision; reward transfer does not permit firing through walls.

Logic review: awards use the existing Marching resource/XP/event path; Story has one shared reward-grant helper. Dead enemies cannot pay twice. Supply receipts report actual capped gains, not a fictitious +20 on a full bar. Nearby magnet motion is clamped to prevent overshoot. No new gameplay currency or save field is introduced; Story damage credit is transient enemy state. One shared opaque reward material and cached geometry keep rendering instanced; every token has fewer than 1,500 vertices, with no extra point lights or transparent gemstone sorting.

Validation: `npm run verify` passes assets, types, 467 tests across 41 files and production build. Regression coverage includes real laser piercing, rocket clusters, tagged-enemy turret finishes beyond 32 m, no duplicate rewards, scrap multipliers, map-supply isolation, resource caps and checkpoint retry. Edge screenshot checks cover desktop/portrait Marching pickups and inventory, a labeled model sheet, all Story chapters at desktop/portrait/landscape sizes, and Story coin/diamond instance counts. Story traversal uses scripted combat resolution rather than a difficulty playtest. See `coin-pickup-review/` for screenshots and the browser report. One initial portrait capture timed out; the clean sequential rerun passed.

The implementation was originally delivered locally. The user subsequently requested publication together with the mobile/PC performance improvements. Git history and the existing GitHub Pages workflow record the release commit and deployment result.
